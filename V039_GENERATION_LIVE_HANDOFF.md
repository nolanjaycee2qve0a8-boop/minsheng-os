## Network secret contract — no plaintext env fallback

The [Cloud environments documentation](https://learn.chatgpt.com/docs/environments/cloud-environments) confirms that programs receive a placeholder for a Network secret and the configured proxy substitutes the original only for allowed HTTPS destinations on443. Unlike the prior implementation, the client now reads the injected placeholder from the requested DEEPSEEK_API_KEY variable and passes it unchanged in the Bearer header; its literal is neither hardcoded nor entered on a CLI. Raw secret values remain outside the process/files under this supported configuration. There is no separate ordinary-variable key fallback or credential-file reader. Needed UI request:

- Key: `DEEPSEEK_API_KEY`, requested for the selected minsheng cloud environment only.
- Type: Network secret, exact target domain `api.deepseek.com`.
- Header: `Authorization`, built as `Bearer ` followed by the platform-injected env placeholder unchanged, without trimming/re-encoding.
- User enters only the actual DeepSeek key in the secure UI; no chat/shell/repository/ledger/log copy. The UI value is the key, not an invented sentinel or guessed JSON.

The [Agents API vault documentation](https://developers.openai.com/api/docs/guides/agents-api/tools/vaults) corroborates passing the named env placeholder unchanged; it is a different product, not the authority for this Cloud environment's settings or port rules. The official Cloud page is primary. No sentinel syntax is invented and no placeholder/key CLI flag exists. Runtime readiness is a trusted-operator assertion that the SAME key is configured only as Network secret (never also a direct variable), the selected environment requests it, and the secure value/network publication are ready. Code cannot independently attest whether an administrator misconfigured an ordinary variable under the same name; that is part of the secure handoff. During this phase all env reads use isolated fake objects; the actual injected env value is NOT inspected. Main reports final published config `87f065b3-cccb-4495-b42f-a70305f30a80~cecfgver_6ac1ce23953c81999de27692790794bd`, but the personal value is unfilled and secretReady is not confirmed. No secret UI is configured here.
